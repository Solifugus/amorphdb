Test Instructions:

This test verifies Step 13: Local Development Mode for offline rendering, Step 12: Shown/Hidden and Focused Updates for section visibility control, Step 11: List Windowing for large list pagination, Step 10: Deep Link Mapper for URL ↔ data synchronization, Step 9: Local Watchers for custom behavior, Step 8: SSE Receiver for real-time server updates, and Step 7: Batch Sender for client-to-server synchronization.

Step 13: Local Development Mode behavior:

  • When SSE connection fails after max attempts, switches to local dev mode automatically
  • Console message: "AmorphDB PWA: Local development mode — no server connection"
  • Template rendering: shows literal {fieldname} text so developers can see what data will go where
  • All proxy, watcher, and DOM update functionality still works locally
  • Batch sender silently skips sending (no error spam in console)
  • Enables offline/serverless development for layout and styling work

Step 11: List Windowing behavior:

  • Each list tracks _from, _through, _total windowing properties automatically
  • Initial load: only first _load_max items are loaded to client data tree
  • Scroll detection: when scrolling near bottom (80%), requests next page automatically
  • MCP message: { type: "list_page", path: "...", from: N, count: N } sent to server
  • Server response: { type: "list_page_response", path: "...", items: [...], from: N, total: N }
  • Eviction: when window exceeds 3x _load_max, items evicted from far end

Step 12: Shown/Hidden and Focused Updates behavior:

  • _shown data attribute: setting to false hides section container (display: none)
  • _shown data attribute: setting to true shows section container (restores original display)
  • Toggle sidebar visibility: data.workspace.sidebar._shown = false/true hides/shows sidebar instantly
  • keepLive(path): registers paths to receive SSE updates regardless of current view
  • Multiple keepLive paths can be registered and stored in a Set
  • shouldReceiveUpdates() checks if a path should get updates (keepLive paths always do)

Step 10: Deep Link Mapper behavior:

  • On page load: reads window.location.pathname and sets data.navigation.current
  • On popstate event (browser back/forward): updates data.navigation.current to match URL
  • Watches navigation.current: when changed via data assignment, pushes URL via history.pushState
  • Prevents infinite loops: skips URL push if window.location.pathname already matches the value
  • Bidirectional sync: URL changes update data, data changes update URL
  • Browser history works: back/forward buttons properly sync with application state

Step 9: Local Watchers behavior:

  • watch(path, callback) registers callbacks for data path changes
  • Watchers fire on exact path matches (banner.app_name watcher fires when banner.app_name changes)
  • Watchers fire on parent path matches (orders watcher fires when orders.0.product changes)
  • Watchers trigger from both proxy sets (local changes) and server updates
  • watch() function exported globally for use in app.js custom logic
  • Error handling: watcher exceptions logged but don't crash other watchers

Step 8: SSE Receiver behavior:

  • Connects to /client-sse/{userId} on initialization
  • Handles connection failures with exponential backoff reconnection
  • Applies server updates directly to rawData (bypassing proxy)
  • Updates DOM surgically without triggering outbound batch sends
  • Stores lastUpdateTime in localStorage for reconnection
  • Simulation mode: Use buttons to test applyServerUpdate without real SSE

Step 7: Batch Sender behavior:

  • All data changes are tracked in a changes Map
  • Changes are batched using queueMicrotask scheduling
  • Single POST request fires after the microtask completes
  • MCP message format: {type: 'data_update', user_id: userId, changes: {path: value}}
  • Changes Map is cleared after successful send
  • Network errors are logged but don't crash the app
